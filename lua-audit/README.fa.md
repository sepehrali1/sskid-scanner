# Sskid Script Scanner — اسکنر استاتیک اسکریپت‌های Lua/Luau

برنامهٔ گرافیکی برای بازرسی **ایستا** اسکریپت‌های Lua/Luau. هیچ فایلی اجرا
نمی‌شود؛ فقط بایت‌ها خوانده می‌شوند.

| فایل | چیست |
|---|---|
| `SskidScriptScanner.bat` | **برنامه** — دوبار کلیک، پنجره باز می‌شود (بدون ترمینال) |
| `dist\SskidScriptScanner.exe` | همان برنامه به‌صورت یک فایل ویندوزی مستقل (نیاز به پایتون ندارد) |
| `sskid_scanner.py` | سورس رابط گرافیکی (tkinter) — صفحهٔ لودینگ + تم تیره |
| `lua_audit.py` | موتور خط فرمان — شش ابزار در یک فایل |
| `web\SskidScanner.html` | **نسخهٔ گوشی** — یک فایل آفلاین که در مرورگر هر گوشی/کامپیوتری باز می‌شود |
| `web\index.template.html` | قالب همان اپ وب (موتور پورت‌شده به JavaScript) |
| `web\build_web.py` | ساخت `SskidScanner.html` از قالب + اسپلش/لوگو |
| `android\` | پروژهٔ اندروید (WebView) + `README.fa.md` برای ساخت APK |
| `make_assets.py` | ساخت اسپلش/لوگو/آیکون از یک عکس دلخواه |
| `assets\` | `splash.png`، `logo.png`، `icon.ico` |
| `build_exe.ps1` | ساخت `dist\SskidScriptScanner.exe` |
| `..\.github\workflows\build-apk.yml` | ساخت APK در فضای ابری گیت‌هاب |

**هیچ‌کدام فایل هدف را اجرا نمی‌کنند** — فقط بایت‌ها را می‌خوانند.
هیچ وابستگی بیرونی ندارد؛ فقط پایتون ۳ استاندارد. تنها بخشی که به شبکه می‌رود
`watch` است (آن هم فقط دو URL ثابت را چک می‌کند).

## برنامهٔ گرافیکی (پیشنهادی)

```
SskidScriptScanner.bat            ← دوبار کلیک
```

اول یک **صفحهٔ لودینگ** با عکس و نوار پیشرفت می‌آید (کلیک یا `Esc` ردش می‌کند)،
بعد پنجرهٔ اصلی باز می‌شود:

1. یک فایل Lua/Luau انتخاب کن (`Ctrl+O`) یا یک پوشه.
2. از سایدبار یکی از شش ابزار را بردار و **اجرا** را بزن (`F5` یا `Ctrl+Enter`).
3. کارت بالا حکم را رنگی نشان می‌دهد: حلقهٔ امتیاز + نوار تهدید/قابلیت.
4. «ذخیره» یا «کپی» برای بردن نتیجه.

میان‌بُرها: `Ctrl+O` انتخاب فایل · `F5` / `Ctrl+Enter` اجرا · `Esc` خروج.

### تم و عکس

پالت برنامه از **رنگ‌های خود عکس** ساخته می‌شود (پیش‌فرض: مشکی + قرمز تیره).
برای عوض کردن عکس:

```powershell
python -X utf8 make_assets.py "C:\path\to\your-image.png"
# assets\splash.png  و  logo.png  و  icon.ico  را می‌سازد و پالت پیشنهادی را چاپ می‌کند
```

### ساخت نسخهٔ exe

```powershell
powershell -ExecutionPolicy Bypass -File .\build_exe.ps1
# خروجی: dist\SskidScriptScanner.exe  (تک‌فایل، بدون نیاز به پایتون، با آیکون و اسپلش)
```

### حالت بدون پنجره (گزارش‌گیری خودکار)

همان exe یک حالت خط فرمان هم دارد؛ برای ساختن گزارش از داخل اسکریپت:

```powershell
SskidScriptScanner.exe --report <file|folder> <out.txt>
```

- اگر مسیر یک فایل باشد، گزارش کامل همان فایل را می‌نویسد.
- اگر پوشه باشد، همهٔ فایل‌ها را بر اساس ریسک مرتب می‌کند.
- اگر مسیر خروجی را ندهی، `sskid-report.txt` ساخته می‌شود.
- برای رد کردن صفحهٔ لودینگ: `--no-splash`.

اگر برنامه هنگام اجرا کرش کند، ردپا در `crash.log` کنار exe
(یا در `%LOCALAPPDATA%\Sskid Script Scanner`) نوشته می‌شود.

## نسخهٔ گوشی (وب + اندروید)

همان اسکنر دو نسخهٔ قابل‌پخش هم دارد:

**۱) اپ وب تک‌فایلی** — `web\SskidScanner.html`

یک فایل ۸۴KB که هیچ چیز بیرونی لازم ندارد (اسپلش و لوگو داخلش جاسازی
شده‌اند). روی هر مرورگری باز می‌شود، آفلاین کار می‌کند، و در مرورگر گوشی
می‌شود «افزودن به صفحهٔ اصلی» زد.

```powershell
cd web
python -X utf8 build_web.py     # از index.template.html می‌سازد
```

موتور آن پورت JavaScript موتور پایتون است و خروجی‌هایش (md5/sha1/sha256،
آنتروپی، امتیاز، حکم، فهرست URL) با نسخهٔ پایتون مو‌به‌مو یکسان تست شده‌اند.
شش تب دارد: بازرسی کامل، هش، رشته‌ها، URLها، اسکن چند فایل، اسلات‌های آنلاین.

**۲) APK اندروید** — پوشهٔ `android\`

پروژهٔ کامل اندروید (AGP 8.5.2، `compileSdk 34`، `minSdk 24`) که همان فایل
وب را در یک `WebView` نشان می‌دهد. ساخت APK روی این سیستم ممکن نیست (سرورهای
اندروید گوگل بلاک‌اند)، ولی سه راه دارد — جزئیات در `android\README.fa.md`:

- **ابری (پیشنهادی):** `.github\workflows\build-apk.yml` را push کن و از تب
  Actions دکمهٔ *Run workflow* را بزن؛ APK ساخته می‌شود و از Artifacts دانلود می‌کنی.
- **محلی:** `android\build_apk.ps1` (نیاز به JDK 17 و Android SDK).
- **Android Studio:** پوشهٔ `android` را باز کن و Build APK بزن.

> صداقت: این APK موتور پایتون را بازنویسی نمی‌کند؛ همان اپ وب را در پوستهٔ
> اندروید اجرا می‌کند. خروجی‌هایش با نسخهٔ ویندوز یکی است.

```powershell
python -X utf8 lua_audit.py <command> ...
```

## دستورها

### ۱. `hash <file>`
هش‌ها و آنتروپی. برای «آیا این فایل با دفعهٔ قبل یکی است؟».

```powershell
python -X utf8 lua_audit.py hash suspicious.lua
```
```
file    ...\suspicious.lua
bytes   834,519
md5     ...
sha1    ...
sha256  bec1f6bd...
entropy 5.190
```

### ۲. `scan <file> [--json]`
گزارش کامل: امتیاز، حکم، یافته‌ها، URLها. کد خروج `1` اگر امتیاز ≥ ۶۰ باشد
(برای استفاده در اسکریپت/CI). با `--json` خروجی ماشین‌خوان می‌دهد.

```powershell
python -X utf8 lua_audit.py scan payload.lua
python -X utf8 lua_audit.py scan payload.lua --json
```

### ۳. `urls <file|dir>`
همهٔ URLهای یک فایل یا یک پوشهٔ کامل، با نام فایل مبدأ. توکن وب‌هوک دیسکورد
**ماسک** می‌شود تا خود ابزار به یک نشتی تبدیل نشود.

```powershell
python -X utf8 lua_audit.py urls .\scripts
```

### ۴. `strings <file>`
رشته‌های خوانا را از داخل فایل بیرون می‌کشد (مثل `strings` یونیکس) و
escapeهای Lua را هم دیکد می‌کند: `\ddd`، `\xNN`، `\n` و… .
برای فایل‌های بسته‌بندی‌شده و باینری مفید است.

```powershell
python -X utf8 lua_audit.py strings payload.lua --min 6 --grep "http|webhook|api"
```

| گزینه | معنی |
|---|---|
| `--min N` | حداقل طول رشته (پیش‌فرض ۴) |
| `--grep RX` | فقط رشته‌های منطبق با این regex |
| `--no-escapes` | دیکد کردن escapeها را رد کن |
| `--width N` | بریدن رشته‌های خیلی بلند در خروجی (پیش‌فرض ۲۴۰) |
| `--limit N` | حداکثر تعداد خط خروجی |

### ۵. `batch <dir> [--min-score N]`
کل یک پوشه را اسکن می‌کند و **بر اساس ریسک** مرتب می‌کند.

```powershell
python -X utf8 lua_audit.py batch .\repo --min-score 25
```
```
SCR  VERDICT    THR   CAP   BYTES    FILE
100  DO NOT RUN 80    48    132253   newbro1
66   DO NOT RUN 60    12    710      script72
...
```

### ۶. `watch [--known known.json]`
دو «اسلات دانلود» شناخته‌شده را چک می‌کند: اگر بایت‌هایشان عوض شده باشد،
یعنی کد جدیدی در صف اجرا برای همهٔ کسانی است که آن‌ها را لود می‌کنند.
`known.json` اختیاری است اگر بخواهی فایل‌های خودت را رصد کنی:

```json
{
  "myslot": {
    "size": 21,
    "sha256": "....",
    "url": "https://raw.githubusercontent.com/.../myslot"
  }
}
```

## امتیاز ریسک چطور حساب می‌شود

امتیاز دو بخش دارد — چون «قدرتمند بودن» و «بدخیم بودن» یکی نیستند:

```
score = min(100, threat + capability / 2)
```

| بخش | یعنی چه | نمونه |
|---|---|---|
| **THREAT** | نشانهٔ آسیب، دزدی یا پنهان‌کاری | `loadstring(HttpGet())`، وب‌هوک، IP-lookup، Kick، anti-tamper، بسته‌بندی‌شده بودن |
| **capability** | قدرتِ خنثی که ابزارهای مشروع هم دارند | `HttpGet`، `http_request`، کلیپ‌بورد، خواندن/نوشتن فایل، هوک، `getgenv` |

چرا جدا؟ چون Dex و F3X و RemoteSpy کلی قابلیت دارند ولی بدافزار نیستند.
اگر همه را یک‌جا جمع می‌زدی، همه‌چیز می‌شد «خطرناک». حالا:

| حکم | شرط | معنی عملی |
|---|---|---|
| `LOW RISK` | score < 25 | چیزی که دیدم مشکوک نبود |
| `REVIEW` | 25 ≤ score < 60 | خودت بخوان؛ یا ناشناخته است یا قابلیت زیادی دارد |
| `DO NOT RUN` | score ≥ 60 | یا کد از راه دور می‌آید/می‌رود، یا پنهان است |

**نکتهٔ مهم:** اگر فایل بسته‌بندی‌شده باشد (WeAreDevs، Luraph، MoonSec و…)،
خروجی `AUDITABLE no` می‌دهد و صریح می‌نویسد که «چیزی پیدا نشد» یعنی
**«نتوانستم ببینم»**، نه «امن است». این همان تله‌ای است که یک اسکنر ساده
در آن می‌افتد و به یک پیلود ۸۰۰KB بسته‌بندی‌شده امتیاز صفر می‌دهد.

## چه چیزی را تشخیص می‌دهد

- دانلود و اجرای کد از راه دور: `loadstring(game:HttpGet(...))`
- وب‌هوک دیسکورد (با ماسک کردن توکن در گزارش)
- IP-lookup (`icanhazip`, `ipify`, …) — نشانهٔ بلوفِ ترساندن یا لاگ واقعی
- کلیپ‌بورد، خواندن/نوشتن فایل، هوک توابع، `getgenv`
- Kick و حلقهٔ بی‌نهایت (فریز کردن کلاینت)
- بسته‌بندها: WeAreDevs، Luraph، PSU، MoonSec، Ironbrew، VM عمومی
- دکوی‌های شناخته‌شده با هش دقیق (مثلاً `print("Hello World")`)
- گلوبال‌های احراز هویت قلابی (`_G.AUTH_KEY` که هیچ‌کس چکش نمی‌کند)

## چه چیزی را نمی‌تواند

- داخل کد بسته‌بندی‌شده را نمی‌بیند. برای آن باید دیکد/دی‌ابفاسکیت کنی؛ ابزار
  فقط می‌گوید «نمی‌شود دید».
- رشته‌هایی که در زمان اجرا رمزگشایی می‌شوند را نمی‌گیرد.
- دربارهٔ نیت قضاوت نمی‌کند. امتیاز = «چه می‌تواند بکند»، نه «چه کسی نوشته».
- هیچ فایلی را اجرا نمی‌کند، پس رفتار واقعی را نمی‌سنجد — فقط ایستا.
